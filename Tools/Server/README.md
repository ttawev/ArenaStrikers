# Свой сервер Арены Страйкеров (VPS)

Сервер — та же игра без графики. Он слушает порт **7777 (UDP)**, держит комнату и считает матч (120 снимков в секунду).
Игроки: «Онлайн» → «Сервер»: адрес → «Подключиться к серверу». Первый вошедший — главный: выбирает формат и начинает матч.
**Версия игры у игроков и на сервере должна совпадать** (номер внизу главного меню; после изменений — пересобрать и то, и другое).

## Наш сервер: ICLOUD.KG «ICLOUD 20» (Ubuntu 24.04)
- Вход по SSH: `ssh -p 10182 root@185.138.184.154` (провайдер пробрасывает 10182 → 22)
- **Адрес для игроков: `77.235.18.42:10184`** (провайдер пробрасывает UDP 10184 → 7777; на втором адресе 185.138.184.154 игровой порт НЕ проброшен — только SSH)
- Пароль root — только у владельца, никому не пересылать.

## 0. Проверка у себя на компьютере (без VPS)
1. Собрать Windows-версию как обычно.
2. Запустить `Tools\Server\run_server_local.bat` — в окне пойдёт журнал сервера. Останавливать — Ctrl+C.
3. В редакторе (Play) или второй копии игры: «Онлайн» → «Сервер»: `127.0.0.1` → «Подключиться к серверу».

## 1. Сборка сервера для Linux
1. Один раз: Unity Hub → Installs → ⚙ у Unity 6.6 → Add modules → **Linux Dedicated Server Build Support** → Install. Перезапустить Unity.
2. Меню **Arena → Собрать сервер (Linux)**. Результат — папка `Builds\Server`.

## 2. Первая настройка сервера (один раз; команды на сервере, по одной)
Войти: `ssh -p 10182 root@185.138.184.154`
```
passwd
adduser --disabled-password --gecos "" arena
mkdir -p /home/arena/server && chown arena:arena /home/arena/server
ufw allow 22/tcp
ufw allow 7777/udp
ufw --force enable
ufw status
exit
```
`passwd` — сменить пароль root (вводится дважды, символы не видны).
`ufw` — брандмауэр: открыт только SSH и порт игры. Порты 22 и 7777 — это порты ВНУТРИ сервера (снаружи — 10182 и 10184).

## 3. Загрузить сервер и запустить (на своём компьютере, PowerShell в папке проекта)
```
cd C:\Users\user\ArenaStrikers
.\Tools\Server\deploy.ps1
```
Скрипт загрузит сборку, включит автозапуск (сервер сам поднимается после перезагрузки и при падении) и покажет статус.
Пароль root спросит несколько раз — это нормально (или настройте вход без пароля, ниже).
Если PowerShell не даёт запустить скрипт: `powershell -ExecutionPolicy Bypass -File .\Tools\Server\deploy.ps1`.

## 4. Играть
«Онлайн» → «Сервер»: `77.235.18.42:10184` → «Подключиться к серверу». Друг делает то же самое.

## Обновление
После изменений в игре: **Arena → Собрать сервер (Linux)** → `.\Tools\Server\deploy.ps1`, и раздать новую Windows-сборку.

## Вход без пароля (по желанию, надёжнее)
На своём компьютере в PowerShell:
```
ssh-keygen -t ed25519
type $env:USERPROFILE\.ssh\id_ed25519.pub | ssh -p 10182 root@185.138.184.154 "mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys"
```
(на вопросы ssh-keygen — просто Enter). Дальше ssh и deploy.ps1 входят без пароля.

## Если что-то не так
- Журнал сервера в реальном времени: `ssh -p 10182 root@185.138.184.154 journalctl -u arena -f` (раз в минуту пишет, кто подключён и пинг; выйти — Ctrl+C).
- Статус: `ssh -p 10182 root@185.138.184.154 systemctl status arena`.
- В игре «Сервер не отвечает»: проверить, что сервис запущен (статус выше), что `ufw status` разрешает 7777/udp, и что у ICLOUD проброс 10184 → 7777 именно по **UDP** и что адрес `77.235.18.42` (не 185.…). У игрока брандмауэр Windows: правило «Block» для игры/Unity в профиле Public — разрешить.
